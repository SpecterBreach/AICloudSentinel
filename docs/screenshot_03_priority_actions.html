CRITICAL AI model bucket has public read access OCI prod-model-weights
Object Storage
LLM02 LLM04 ASI08
CLAUDE AI
An adversary discovers the bucket name via passive reconnaissance or OCI Storage URL enumeration, downloads the fine-tuned model weights, then either re-hosts the model commercially or reverse-engineers training data to reconstruct proprietary datasets — all without any authentication.
CLAUDE AI
  1. Set public_access_type=NoPublicAccess in OCI Console → Object Storage → Edit Bucket
  2. Audit existing pre-authenticated requests (PARs) — revoke any with indefinite expiry
  3. Enable OCI Object Storage access logs → route to a SIEM for alerting
  4. Add a bucket policy explicitly denying public principals
  5. Rotate any credentials that may have been used to access the bucket
CRITICAL LLM API key exposed in Function config (plaintext) OCI ai-inference-fn
OCI Function
LLM07 ASI04
CLAUDE AI
An insider or compromised CI/CD principal with functions:GetFunction reads the config, extracts the API key, then runs unbounded LLM inference — accumulating thousands in provider costs — or uses the key to exfiltrate conversation history from the provider's API logs.
CLAUDE AI
  1. Rotate the exposed key immediately in the LLM provider dashboard
  2. Create an OCI Vault secret for the new key
  3. Update Function config to reference Vault secret OCID instead of plaintext value
  4. Grant Function dynamic group secret-bundles:read on the specific secret only
  5. Scan all other Functions and App configs for similar patterns
HIGH AI/GPU EC2 instance has IMDSv1 enabled (unauthenticated) AWS llm-worker-p3.2xl
EC2 Instance
LLM02 ASI04 ASI08
CLAUDE AI
A prompt injection attack against the LLM inference endpoint triggers an outbound HTTP request to 169.254.169.254/latest/meta-data/iam/security-credentials/, returning temporary AWS credentials — giving the attacker full access to every service the instance role permits without touching a password.
CLAUDE AI
  1. Set HttpTokens=required via EC2 console → Actions → Instance Settings → Modify instance metadata options
  2. Apply account-wide SCP: ec2:ModifyInstanceMetadataOptions deny without imdsv2 condition
  3. Enable AWS Config rule ec2-imdsv2-check in all regions
  4. Scope the instance IAM role to minimum required permissions for inference workload
HIGH Azure AI Services account has unrestricted public access Azure openai-prod-eastus
Cognitive Services
LLM02 LLM10 ASI04
CLAUDE AI
An attacker who obtains a static API key (from a leaked .env file, a public GitHub repo, or a compromised developer machine) can make unrestricted calls to the Azure OpenAI endpoint from any IP — running prompt injection campaigns, exfiltrating conversation context, or exhausting the token quota causing service disruption for legitimate applications.
CLAUDE AI
  1. Set publicNetworkAccess=Disabled and configure Azure Private Endpoint
  2. Set disableLocalAuth=true to force Entra ID authentication
  3. Assign callers the Cognitive Services User role via RBAC
  4. Enable Diagnostic Settings → route logs to Azure Monitor / Sentinel
  5. Rotate both API keys via Azure Portal → Keys and Endpoint
